Sorting — overview

Sorting is a problem with many valid solutions. Every algorithm on this page produces the same correct, ordered output — what separates them is how they get there, and at what cost.

Why so many sorting algorithms?

If correctness were the only requirement, one algorithm would be enough. In practice, the right choice depends on input size, how the data starts out, memory constraints, and whether you need the sort to be stable (equal elements keep their relative order). Complexity — time and space — is the main lens this guide uses to tell them apart.

The six core algorithms

This series covers six algorithms in depth, each with its own dedicated walkthrough and C++ implementation. A handful of less common ones — Shell, Counting, Radix, Bucket, and Tim Sort — are deferred to a future advanced guide.

AlgorithmIn shortAverage time
Bubble sortRepeatedly swaps neighboring out-of-order pairsO(n²)
Selection sortFinds the minimum remaining element, places itO(n²)
Insertion sortBuilds the sorted section one element at a timeO(n²)
Merge sortSplits, sorts halves recursively, merges themO(n log n)
Quick sortPartitions around a pivot, recurses on each sideO(n log n)
Heap sortBuilds a heap, repeatedly extracts the maxO(n log n)

Choosing one

As a rule of thumb: the three O(n²) algorithms are simple to write and reason about but don't scale — useful for learning, small inputs, or nearly-sorted data (insertion sort in particular). The three O(n log n) algorithms are what you'd actually reach for on real workloads; which of them depends on whether you can afford merge sort's extra memory, need quick sort's typically-fast average case, or want heap sort's guaranteed worst case.

Algorithms

A data structure decides how values are stored; an algorithm is the procedure you run over them to get an answer. The same problem usually has several correct procedures, and the interesting difference between them is cost — how the work grows as the input grows.

How this section is organised

The first two groups are concrete techniques you apply directly. Everything after them is a paradigm: a way of shaping a solution that applies across many different problems. Recognising which paradigm a problem wants is most of the work in an interview.

Choosing an approach

Problems rarely announce which paradigm they want, but the phrasing gives it away. This is the table to scan when you're stuck on where to start.

Approach Core idea Typical cost The problem sounds like
Binary search Halve the search space each step O(log n) "Find a value in sorted data" — or "find the smallest x that works".
Sorting Impose order, then exploit it O(n log n) "Rank", "group duplicates", "find the k-th largest".
Divide and conquer Split, solve the halves, combine O(n log n) "The answer for the whole is built from the answers for the parts."
Greedy Commit to the best immediate choice O(n log n) "Maximum number of non-overlapping…", "minimum coins", scheduling.
Backtracking Explore every choice, undo on failure Exponential "List all…", "every valid arrangement", puzzle-shaped constraints.
Dynamic programming Reuse overlapping subproblem answers O(n·m) "Count the ways", "minimum cost to…", with choices repeating.
Graph traversal Visit vertices, never twice O(V + E) "Reachable", "shortest path", "connected", "order of dependencies".
Greedy and DP answer the same question differently

Both build a solution from a sequence of choices. Greedy makes each choice once and never revisits it, which is fast but only correct when a local best is provably part of a global best. Dynamic programming keeps every choice open and compares the outcomes, which always works but costs memory. When a greedy solution fails a test case, DP is usually the fix.

Complexity is about growth, not speed

An O(n²) algorithm can beat an O(n log n) one on small inputs — insertion sort is genuinely faster than merge sort for a few dozen elements, which is why real library sorts switch to it near the bottom of the recursion. Big-O tells you what happens as n grows, not which is faster today.

How to read this section

Suggested order

Searching and sorting first — they're small enough to trace by hand, and every later page reuses their vocabulary. Recursion next, because divide and conquer, backtracking and DP are all recursion with something added: a split, an undo, or a cache. Then greedy and backtracking as the two opposite instincts, DP as the reconciliation, and graph algorithms last, where all of it comes together. Strings and maths stand on their own and can be read whenever you need them.

Not the same as patterns

The common patterns section covers techniques like two pointers and sliding window. Those are ways of moving through data rather than full algorithms, so they live separately — but they show up constantly inside the algorithms here.

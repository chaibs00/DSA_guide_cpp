Core concepts

Complexity analysis

Complexity analysis measures how the cost of an algorithm grows when the input gets bigger. It is written with Big-O notation, like O(n) or O(n²).

The same input size, five different growth rates.

Big-O notation

Big-O describes the growth of an algorithm, not its exact runtime. We count the operations, then keep only the part that grows fastest.

Click to expand

Two rules are used every time:

  • Drop the constants. 3n becomes O(n).
  • Keep only the biggest term. n² + n + 50 becomes O(n²).
counting.cpp
int f(vector<int>& v) {
    int total = 0;                          // 1

    for (int x : v)                         // n
        total += x;

    for (int i = 0; i < v.size(); i++)      // n
        for (int j = 0; j < v.size(); j++)  // n  -> n * n
            total += v[i] * v[j];

    return total;                           // 1
}
// 2 + n + n²  ->  O(n²)
Note

Big-O is the worst case. There is also Ω for the best case and Θ when both are the same, but Big-O is what people use most of the time.

Reading complexity from the code

Three rules cover most cases: loops one after another are added, nested loops are multiplied, and cutting the input in half gives a logarithm.

Click to expand — constant, linear, quadratic, logarithmic

O(1) — constant

The work does not depend on the input size. Reading v[0] takes the same time in an array of 10 or 10 million.

constant.cpp
int first(vector<int>& v) {
    return v[0];      // one step
}

O(n) — linear

One loop over the input. If the input doubles, the work doubles.

linear.cpp
int findMax(vector<int>& v) {
    int best = v[0];

    for (int x : v) {            // n times
        if (x > best) best = x;
    }

    return best;
}

Two loops one after another give n + n = 2n, which is still O(n). Only nested loops multiply.

O(n²) — quadratic

A loop inside a loop. Each element is compared with every other element.

quadratic.cpp
bool hasDuplicate(vector<int>& v) {
    for (int i = 0; i < v.size(); i++)          // n
        for (int j = i + 1; j < v.size(); j++)  // n
            if (v[i] == v[j]) return true;

    return false;
}
// O(n²)
Note

The inner loop starts at i + 1, so it runs about n²/2 times. The constant is dropped, so it is still O(n²).

O(log n) — logarithmic

Each step removes half of what is left. Searching 1,000,000 sorted elements takes about 20 steps.

logarithmic.cpp
int binarySearch(vector<int>& v, int target) {
    int lo = 0, hi = v.size() - 1;

    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;

        if (v[mid] == target) return mid;
        if (v[mid] < target)  lo = mid + 1;   // drop the left half
        else                  hi = mid - 1;   // drop the right half
    }

    return -1;
}
Tip

A loop with i++ is linear. A loop with i *= 2, or one that halves a range, is logarithmic.

Watch out

At n = 1,000,000, an O(n log n) algorithm needs about 20 million operations. An O(n²) one needs a trillion.

Space complexity

The same idea, applied to memory: how much extra memory the algorithm needs. The input itself is not counted.

Click to expand

O(1) — in place

Only a few variables, whatever the input size.

in_place.cpp
void reverse(vector<int>& v) {
    int lo = 0, hi = v.size() - 1;   // two ints

    while (lo < hi) {
        swap(v[lo], v[hi]);
        lo++; hi--;
    }
}
// time O(n), space O(1)

O(n) — extra memory

A new container that grows with the input.

extra_space.cpp
vector<int> doubled(vector<int>& v) {
    vector<int> out;                 // n elements

    for (int x : v) out.push_back(x * 2);

    return out;
}
// time O(n), space O(n)

Recursion uses memory too

Each recursive call keeps a frame on the stack until it returns, so the depth of the recursion is memory.

recursion_space.cpp
int sum(int n) {
    if (n == 0) return 0;
    return n + sum(n - 1);   // n frames at the same time
}
// time O(n), space O(n)
Tip

Time and memory can often be traded. A hash map gives O(1) lookup but uses O(n) memory.

Amortized complexity

The average cost of an operation over many calls, when a few calls are expensive. push_back is usually O(1), but when the vector is full it allocates a bigger block and copies everything, which is O(n).

amortized.cpp
vector<int> v;

for (int i = 0; i < n; i++)
    v.push_back(i);    // usually O(1), sometimes O(n)

// n insertions cost O(n) in total -> O(1) amortized

The capacity doubles each time, so the copies get rarer as the vector grows.

How to analyze a piece of code

Five steps that cover most cases.

Click to expand
  1. Find n. It is the input whose size changes the cost. With two inputs, write O(n + m).
  2. Count the loops. Loops in sequence are added, nested loops are multiplied.
  3. Check the calls inside. An O(n) call inside an O(n) loop gives O(n²).
  4. Count the extra memory. New containers, plus the recursion depth.
  5. Simplify. 4n² + 100n + 7 becomes O(n²).
Watch out

Big-O hides the constants. On small inputs an O(n²) algorithm can be faster than an O(n log n) one. Use complexity to choose, then measure.

Core concepts

Recursion

A recursive function is a function that calls itself. Each call works on a smaller version of the problem, until the problem is small enough to answer directly.

Nothing is computed on the way down. The multiplications happen on the way back up.

Base case and recursive case

Every recursive function needs two parts. The base case returns an answer without calling itself. The recursive case calls the function on a smaller input.

Click to expand
factorial.cpp
int fact(int n) {

    if (n <= 1) return 1;       // base case

    return n * fact(n - 1);     // recursive case
}

Two things must be true or the function never stops:

  • The input gets smaller at every call.
  • It always reaches the base case.
Watch out

fact(n - 1) gets smaller, but fact(n / 2) with n = 1 stays at 0 forever if the base case only checks n == 1. Check that the base case is actually reachable from every input.

How the call stack works

Each call gets its own stack frame holding its parameters and local variables. The frame stays alive until the call returns, so during fact(4) there are four frames in memory at once.

Click to expand — step by step

Calling fact(4) runs in this order:

trace.txt
fact(4)  ->  needs fact(3)
fact(3)  ->  needs fact(2)
fact(2)  ->  needs fact(1)
fact(1)  ->  returns 1        base case

fact(2)  ->  returns 2 * 1  = 2
fact(3)  ->  returns 3 * 2  = 6
fact(4)  ->  returns 4 * 6  = 24

The first half is the calls going down, the second half is the results coming back. This is why recursion uses memory: the frames of the calls that are still waiting cannot be freed yet.

Note

The space complexity of a recursive function is at least O(depth), even when it allocates nothing itself.

Recursion vs iteration

Anything written with recursion can be written with a loop, and the other way around. The choice is about which one is easier to read for the problem.

Click to expand — the same function both ways
both_ways.cpp
// recursive
int factRec(int n) {
    if (n <= 1) return 1;
    return n * factRec(n - 1);
}

// iterative
int factIter(int n) {
    int result = 1;

    for (int i = 2; i <= n; i++)
        result *= i;

    return result;
}

Tip

Use recursion when the data itself is nested — trees, graphs, folders, nested JSON. Use a loop when you are just counting or scanning a list.

Recursion that branches

When a function calls itself more than once, the calls form a tree instead of a straight line. This is where recursion gets expensive.

The call tree for fib(4). Teal nodes are base cases, red nodes are repeated work.

Click to expand — the problem and the fix

The slow version

fib_slow.cpp
int fib(int n) {
    if (n <= 1) return n;

    return fib(n - 1) + fib(n - 2);   // two calls per call
}
// O(2ⁿ) — fib(50) takes years

Each call makes two more calls, so the number of calls roughly doubles at every level. The same values are recomputed again and again.

Memoization

Store each result the first time it is computed, and reuse it after that.

fib_memo.cpp
long long fib(int n, vector<long long>& memo) {
    if (n <= 1) return n;

    if (memo[n] != -1) return memo[n];    // already computed

    memo[n] = fib(n - 1, memo) + fib(n - 2, memo);
    return memo[n];
}

int main() {
    int n = 50;
    vector<long long> memo(n + 1, -1);
    cout << fib(n, memo);
}
// O(n) — each value is computed once
Tip

Recursion plus memoization is the base of dynamic programming. If a recursive function is slow, first check whether it is solving the same subproblem more than once.

Common mistakes

Most recursion bugs come from three places.

Click to expand

Missing or unreachable base case

The function keeps calling itself, the stack fills up, and the program crashes with a stack overflow.

no_base.cpp
int bad(int n) {
    return n * bad(n - 1);    // never stops
}

Depth too large

Even with a correct base case, a depth of a few hundred thousand can overflow the stack. A loop has no such limit.

deep.cpp
int sum(int n) {
    if (n == 0) return 0;
    return n + sum(n - 1);
}

sum(1000000);   // likely stack overflow

Forgetting to return the recursive call

The call runs, but the result is thrown away.

no_return.cpp
int bad(int n) {
    if (n <= 1) return 1;

    n * bad(n - 1);    // ✗ result discarded
    return n * bad(n - 1);   // ✓
}

Where recursion is used

Recursion fits problems whose structure repeats inside itself.

Click to expand
AreaWhy recursion fits
Tree traversalEach subtree is a smaller tree
Graph search (DFS)Each neighbour starts the same search again
Merge sort, quicksortSplit the array, sort each half the same way
Binary searchSearch one half with the same function
BacktrackingTry a choice, recurse, undo it and try the next

A short example — the sum of every node in a binary tree, which is hard to write with a loop and short with recursion:

tree_sum.cpp
struct Node {
    int data;
    Node* left;
    Node* right;
};

int treeSum(Node* root) {
    if (root == nullptr) return 0;    // base case

    return root->data
         + treeSum(root->left)
         + treeSum(root->right);
}

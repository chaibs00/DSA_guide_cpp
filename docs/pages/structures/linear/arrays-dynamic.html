Linear data structures/Arrays

Dynamic arrays

A dynamic array can change size at runtime, with its memory allocated on the heap. In C++ you get one through std::vector, which handles that memory for you.

Declaration

Using std::vector

Include <vector> first. The four forms below cover almost every case you'll write.

declare.cpp
#include <vector>
using namespace std;

vector<int> v1;              // empty                  → { }
vector<int> v2(5);           // size 5, all zeros      → {0, 0, 0, 0, 0}
vector<int> v3(5, 10);       // size 5, all tens       → {10, 10, 10, 10, 10}
vector<int> v4 = {1, 2, 3};  // initialiser list       → {1, 2, 3}

Manual allocation with new

You can also allocate a block yourself. This lives on the heap rather than the stack, and nothing frees it automatically.

manual.cpp
// allocate an array of size 5 on the heap
int* arr = new int[5];

// values must be assigned manually
arr[0] = 12;

// release the memory allocated by new
delete[] arr;
Watch out

Memory you allocate with new is yours to free. Forget the matching delete[] and it leaks. Values are not initialised either, so reading before assigning gives you garbage. std::vector exists precisely so you don't have to get this right.

Accessing elements

First and last

front_back.cpp
vector<int> v = {3, 2, 1};

v.front();   // 3 — first element
v.back();    // 1 — last element

By index

Two ways to reach index i: the subscript operator, or .at().

index.cpp
vector<int> v = {3, 2, 1};

v[0];      // 3
v.at(0);   // 3

v[6];      // no bounds check — garbage or undefined behaviour
v.at(6);   // throws std::out_of_range
Which one

v[i] is faster because it checks nothing. v.at(i) is safer because it throws when the index is invalid. Use .at() while you're learning or when the index comes from outside your code.

Adding elements

At the back

push_back.cpp
vector<int> v = {3, 2, 1};

v.push_back(10);   // v = {3, 2, 1, 10}

At a given index

insert(position, value) takes an iterator, not an index. v.begin() points at the first element, so v.begin() + i points at index i.

insert.cpp
vector<int> v = {3, 2, 1};

// insert 10 at index 1
v.insert(v.begin() + 1, 10);   // v = {3, 10, 2, 1}

Removing elements

pop_back() drops the last element and shrinks the size by one; clear() empties the whole thing.

remove.cpp
vector<int> v = {3, 8, 1, 4};

v.pop_back();   // v = {3, 8, 1}, size is now 3
v.clear();      // v = { }

erase() removes at a position — everything after it shifts one place left, which is why this costs O(n).

erase.cpp
vector<int> v = {3, 8, 1, 4};

v.erase(v.begin());       // remove the first  → {8, 1, 4}
v.erase(v.begin() + 2);   // remove index 2    → {8, 1}

Traversal

Index-based

Needs the size, which .size() gives you directly — no sizeof arithmetic here.

traverse_index.cpp
vector<int> v = {3, 2, 1, 4};

for (int i = 0; i < v.size(); i++) {
    cout << v[i] << " ";
}
// 3 2 1 4

Range-based

traverse_range.cpp
vector<int> v = {3, 2, 1, 4};

for (int x : v) {
    cout << x << " ";
}
// 3 2 1 4

Size and capacity

A vector tracks two numbers. Size is how many elements are stored; capacity is how many it can hold before it must find a bigger block. When size would exceed capacity, the vector allocates elsewhere and copies everything across.

The reallocation copies every existing element, so that one push_back() costs O(n) — while every other call is O(1).

2-dimensional arrays

Everything so far has been one-dimensional. A matrix is just a vector whose elements are themselves vectors.

Declaration

matrix_declare.cpp
// 3 rows × 4 columns, every element 0
vector<vector<int>> M(3, vector<int>(4, 0));

// same shape — elements get the default value (0)
vector<vector<int>> M(3, vector<int>(4));

// size unknown up front: declare, then resize
vector<vector<int>> M;
M.resize(3, vector<int>(4, 0));

Accessing an element

Two indices, always in the order [row][column]: the first picks the row, the second the column within it.

matrix_access.cpp
vector<vector<int>> M(3, vector<int>(4));

M[0][0];   // first row, first column
M[1][2];   // second row, third column
M[2][3];   // last valid cell of a 3 × 4 matrix

Row index down the left, column index across the top.

Traversal

M.size() is the number of rows; M[i].size() is the number of columns in row i. Two nested loops cover the grid.

matrix_traverse.cpp
vector<vector<int>> M(3, vector<int>(4, 0));

int rows = M.size();      // 3
int cols = M[0].size();   // 4

// index-based
for (int i = 0; i < M.size(); i++) {
    for (int j = 0; j < M[i].size(); j++) {
        cout << M[i][j] << " ";
    }
    cout << endl;
}

// range-based
for (auto &row : M) {
    for (auto &val : row) {
        cout << val << " ";
    }
    cout << endl;
}
Tip

Use & in a range-based loop over a matrix. Without it each row is copied on every iteration, which turns a cheap traversal into an expensive one.

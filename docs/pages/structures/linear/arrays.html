Data structures/Linear data structures

Arrays

The array is the simplest possible data structure: values sitting one after another in memory. Everything else in this guide — vectors, strings, even linked lists — is either built on this idea or defined in contrast to it.

Static arrays

A C-style array reserves a fixed block of contiguous memory when it's declared. Its size is baked in at compile time and can't change afterward.

Each element sits 4 bytes after the last (for an int) — that's what "contiguous" means, and it's why arr[i] is O(1).

static_array.cpp
int scores[5] = {4, 8, 15, 16, 23};

// Direct access by index — O(1), no matter how big the array is
int third = scores[2]; // 15

// Size is fixed — this will NOT compile:
// scores[5] = 42;   // out of bounds, undefined behavior
Watch out

C++ does not check array bounds for you. Reading or writing past the end of a static array is undefined behavior, not a clean crash — it may silently corrupt other memory.

Dynamic arrays — std::vector

A std::vector looks like an array but manages its own memory. It tracks two numbers: size (elements you've added) and capacity (room already reserved). When size would exceed capacity, the vector allocates a bigger block elsewhere and copies everything over.

Reallocation copies every existing element to the new block — that single push_back() costs O(n), even though most calls are O(1).

dynamic_array.cpp
#include <vector>

std::vector<int> scores = {4, 8, 15, 16};

scores.push_back(23);       // usually O(1), occasionally O(n) on reallocation
int third = scores[2];      // O(1), same as a static array

scores.size();               // 5 — elements actually stored
scores.capacity();           // 8 — room currently reserved

Traversal

Whether it's static or dynamic, visiting every element is the same O(n) operation you saw on the complexity page — one step per element, no shortcuts.

Static arraystd::vector

Tip

Reach for std::vector by default. Only drop to a raw array when you have a fixed, known size and a specific reason to avoid the small overhead std::vector carries.

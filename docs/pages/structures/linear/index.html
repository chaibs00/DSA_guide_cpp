Data structures

Linear data structures

Elements sit in one sequence: each has at most one predecessor and one successor, so you can walk from the first to the last without ever choosing a branch. What separates them is where you're allowed to add, remove and read.

How they differ

Same family, different rules of access. This is the table to come back to when you're deciding which one a problem wants.

Structure Memory Access Insert / erase Where it fits
Array Contiguous block By index — O(1) At the end O(1)*, elsewhere O(n) Known-size data you read far more than you reshape.
String Contiguous block By index — O(1) At the end O(1)*, elsewhere O(n) Text: an array of characters with text tooling on top.
Linked list Scattered nodes + pointers By traversal — O(n) O(1) once you hold the node Frequent insertion or removal in the middle.
Stack Array or list underneath Top element only — O(1) One end only — O(1) Undo, recursion, backtracking, matching brackets.
Queue Array or list underneath Front element only — O(1) Back in, front out — O(1) Scheduling, buffering, breadth-first search.

* Amortised: appending is constant on average, but an occasional reallocation copies everything.

Strings aren't really a data structure

A string is a data type, not a data structure of its own — underneath it is an array of characters. We give it a page anyway because in practice you use it exactly like a linear structure, and interview problems treat it as one: the same two-pointer, sliding-window and traversal techniques apply directly.

How to read this section

Suggested order

Start with arrays and strings to get comfortable with indexing and contiguous memory. Then linked lists, which trade indexing for cheap insertion and introduce pointers as the connective tissue. Stacks and queues come last: both are restricted views over what you already know, so the interesting part is when the restriction helps, not how it's built.

Data structures

Non-linear data structures

Elements form a hierarchy or a network rather than a sequence: one element can connect to many others, so there is no single path from first to last. You reach a value by choosing a route, not by counting positions.

What changes

Dropping the one-predecessor-one-successor rule has three consequences, and they shape every page in this section.

  • There is no single traversal order. You pick one — depth-first, breadth-first, in-order — and the choice changes the result.
  • Position stops meaning anything. There is no "index 4"; you follow pointers or compute where a value should live.
  • Cycles become possible. A graph walk that doesn't record visited vertices runs forever.

What we cover here

Nine structures, ordered from the one everything else borrows from to the ones you'll only reach for once problems get harder. Trees come first because heaps, tries and balanced trees are all trees with one extra rule attached.

How they differ

Average-case costs for the operation each structure is actually chosen for. n is the element count, L a key's length, V and E the vertex and edge counts.

Structure Shape Search Insert Erase Where it fits
Binary search tree Hierarchy O(log n) O(log n) O(log n) Lookup that also keeps things sorted.
Heap Hierarchy O(n) O(log n) O(log n) Repeatedly taking the smallest or largest item.
Hash table Buckets O(1)* O(1)* O(1)* Key lookup when you don't need any ordering.
Trie Hierarchy O(L) O(L) O(L) Prefix matching and autocomplete.
Graph Network O(V + E) O(1) O(E) Arbitrary relationships: maps, dependencies, routes.
Disjoint set Forest O(α(n)) O(α(n)) — Answering "are these two connected?" repeatedly.
Segment tree Hierarchy O(log n) O(log n) — Range queries over data that keeps updating.

* Average case. With a poor hash function or a deliberately hostile input, all three degrade to O(n).

Averages hide the bad case

Insert already-sorted data into a plain BST and every node becomes an only child — the tree is a linked list wearing pointers, and O(log n) becomes O(n). That single failure is why balanced trees exist, and why std::map is a red-black tree rather than the naive version.

You have already used these

std::map and std::set are balanced trees; std::unordered_map and std::unordered_set are hash tables; std::priority_queue is a heap. Knowing what sits underneath is what tells you which to reach for — and why iterating a map comes out sorted while an unordered_map does not.

How to read this section

Suggested order

Start with trees: the vocabulary and the traversals carry into everything after. Binary search trees add an ordering rule and heaps add a different one, so both read easily once trees are solid. Hash tables stand apart and can be read at any point. Graphs come next, reusing traversals you already know but now with cycles to guard against. Leave disjoint sets, balanced trees and segment trees until a problem asks for them.

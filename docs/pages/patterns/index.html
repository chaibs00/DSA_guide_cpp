Common patterns

Most interview problems are not new problems. They are a small set of techniques wearing different stories, and once you can name the technique a problem wants, the code is usually short. This section collects the ones that keep coming back.

What a pattern actually is

A pattern is smaller than an algorithm. Binary search is an algorithm — it has a name, a proof and a fixed cost. "Two pointers" is a way of moving through data that shows up inside dozens of different algorithms. You don't implement a pattern; you recognise one and it tells you what shape your loop takes.

The payoff is speed of recognition. A problem that reads as "longest substring with at most k distinct characters" is a sliding window before you've thought about it, and that one observation removes the brute-force O(n²) attempt entirely.

The shape most of them share

Two pointers, sliding window and monotonic stacks are all the same skeleton: one index moves forward unconditionally, another moves forward only when a condition says it should. Recognising that keeps the implementations from feeling like ten separate things to memorise.

window_skeleton.cpp 
int left = 0;
for (int right = 0; right < n; ++right) {
    add(a[right]);                 // the window grows

    while (!valid()) {             // it shrinks only when it must
        remove(a[left]);
        ++left;
    }

    best = max(best, right - left + 1);
}

Every element enters once and leaves once, which is why the nested while doesn't make this quadratic.

Patterns are a starting point, not an answer

Matching a problem to a pattern tells you which loop to write; it doesn't tell you the edge cases. Empty input, a window of size one, all-equal values and integer overflow break pattern-matched solutions far more often than the main logic does.

How to actually learn these

Solve three or four problems per pattern in a row rather than one of each. Recognition comes from seeing the same technique in different clothing, and it doesn't develop when the problems are shuffled. After each one, write down the sentence in the problem that gave the pattern away — that list becomes worth more than the solutions.

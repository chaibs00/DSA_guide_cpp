Where variables stop being names and start being addresses: memory addresses, pointers, how arguments really travel into functions, and manual allocation on the heap.

Why this matters for DSA

Linked lists, trees, and graphs are all built from nodes that point at other nodes. Everything on this page is the vocabulary those structures are written in.

1. Memory addresses

A memory address is a location in the computer's memory where data is stored. In C++ you can read the address of a variable with the address-of operator (&).

Click to expand

Display the address of a variable

address.cpp
int a = 10;
std::cout << "The address of a is: " << &a;
output
The address of a is: 0x7ffe413feecc

Memory addresses are usually printed in hexadecimal (base 16).

  • 0x7ffe413feecc = 140729993129676 in decimal
Note

The exact address changes on every run — the operating system decides where your variables live.

2. Pointers

A pointer is a variable that stores the memory address of another variable, letting you manipulate data directly in memory.

Click to expand

Syntax

  • & — address-of operator: gets the address of a variable
  • * — dereference operator: accesses the value stored at an address
pointer.cpp
int x = 10;
int *ptr = &x;  // ptr holds the address of x

std::cout << "Address of x: " << &x << std::endl;
std::cout << "Value stored at *ptr: " << *ptr << std::endl;
output
Address of x: 0x7fffb81dedd4
Value stored at *ptr: 10

Null pointers

A null pointer points to nothing — it signals that the pointer is not currently pointing at a valid memory location.

null-pointer.cpp
int *ptr = nullptr;  // initialize the pointer as null

if (ptr == nullptr) {
    std::cout << "The pointer was not assigned to an address yet";
}
Watch out

Dereferencing a null pointer is unsafe and usually crashes the program. Always check for nullptr first.

unsafe.cpp
int *ptr = nullptr;
std::cout << *ptr;  // unsafe — undefined behaviour

3. Pass by value, reference, and address

Understanding how data travels into a function is essential for writing efficient C++ — and for knowing when a function can change your data.

Click to expand

Pass by value

A copy of the original variable is created. Changes made inside the function do not affect the original.

pass-by-value.cpp
#include <iostream>
using namespace std;

void swapByValue(int a, int b) {
    int temp = a;
    a = b;
    b = temp;
}

int main() {
    int x = 5, y = 10;
    swapByValue(x, y);  // x = 5, y = 10 (unchanged)
    return 0;
}
output
x = 5
y = 10

Result: x and y are unchanged — the copies were swapped, not the originals.

Pass by reference

The function receives a reference to the original variable and works directly on the original data.

pass-by-reference.cpp
#include <iostream>
using namespace std;

void swapByReference(int &a, int &b) {
    int temp = a;
    a = b;
    b = temp;
}

int main() {
    int x = 5, y = 10;
    swapByReference(x, y);  // x = 10, y = 5 (swapped)
    return 0;
}
output
x = 10
y = 5

Result: x and y are swapped because the function reaches the original memory locations.

Pass by address (pointers)

You pass the memory address of the variable. References let you use the variable directly; pointers require the dereference operator (*) to reach the value.

pass-by-address.cpp
#include <iostream>
using namespace std;

void swapByAddress(int *a, int *b) {
    int temp = *a;
    *a = *b;
    *b = temp;
}

int main() {
    int x = 5, y = 10;
    swapByAddress(&x, &y);  // x = 10, y = 5 (swapped)
    return 0;
}
output
x = 10
y = 5

Result: x and y are swapped because the function holds their addresses.

Way of passingSignatureCallChanges original?
By valuevoid f(int a)f(x)no
By referencevoid f(int &a)f(x)yes

4. Dynamic memory (heap)

Dynamic memory is memory allocated at runtime, while the program is running. It's what you use when you don't know how much memory you'll need in advance.

Click to expand

Heap vs stack

StackHeap
Allocated automatically when variables are declaredAllocated manually with new
Freed automatically when the function returnsMust be freed manually with delete
Limited sizeLarger and more flexible
Faster accessSlower access

Allocating memory — new

The new operator allocates memory on the heap and returns its address.

new.cpp
// dynamically allocate memory for an integer
int* ptr = new int;

// assign a value to the allocated memory
*ptr = 10;

Deallocating memory — delete

Once you're done with dynamic memory you must free it, or you leak it.

delete.cpp
delete ptr;  // deallocate the memory ptr points to
Memory leaks

A memory leak happens when allocated memory is never deallocated. The memory stays reserved but is no longer reachable, consuming resources for nothing.

Proper memory management:

manage.cpp
int* ptr = new int;
*ptr = 42;

// use the pointer...

delete ptr;    // free the memory
ptr = nullptr; // good practice: null it out after deleting

Dynamic arrays

dynamic-array.cpp
int* arr = new int[5];  // allocate an array of 5 integers

// use the array...

delete[] arr;  // use delete[] for arrays
Rule of thumb

Match the pair: new goes with delete, and new[] goes with delete[].

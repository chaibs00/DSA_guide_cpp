Core concepts

Complexity analysis

Before you learn a single data structure, you need a way to compare them. Big-O notation is that yardstick — it describes how an algorithm's cost grows as its input grows, not how fast it runs on your machine today.

Why complexity matters

Two pieces of code can solve the same problem and both "work" on a small test case, yet behave completely differently once the input reaches real-world size. Complexity analysis tells you which one that will be, without having to run either.

It comes in two flavors, and you'll see both used throughout this guide:

  • Time complexity — how the number of operations grows as input size (n) grows.
  • Space complexity — how much extra memory the algorithm needs as n grows.

Reading Big-O notation

Big-O describes the worst-case growth rate, ignoring constants and lower-order terms. O(2n + 5) is just O(n) — as n gets large, the +5 becomes irrelevant and the 2 doesn't change the shape of the curve.

Growth of common complexity classes as input size increases — shape matters, not the exact numbers.

Time complexity in code

Here's the same idea across three loop shapes. Watch how the number of nested loops over n maps directly to the exponent in the notation.

constant.cpp
// O(1) — cost doesn't depend on the size of arr
int getFirst(const std::vector<int>& arr) {
    return arr[0];
}
linear.cpp
// O(n) — one pass over every element
int sum(const std::vector<int>& arr) {
    int total = 0;
    for (int x : arr) {
        total += x;
    }
    return total;
}
quadratic.cpp
// O(n^2) — a nested loop over the same input
bool hasDuplicate(const std::vector<int>& arr) {
    for (size_t i = 0; i < arr.size(); i++) {
        for (size_t j = i + 1; j < arr.size(); j++) {
            if (arr[i] == arr[j]) return true;
        }
    }
    return false;
}
Tip

When you see nested loops that each scan the full input, that's a strong signal you're looking at O(n²) — and a strong hint to ask whether a hash set or sorting step could bring it down to O(n) or O(n log n).

Space complexity

Space complexity follows the same logic, but counts memory instead of steps. sum() above uses O(1) extra space — one int accumulator, regardless of how big arr is. A function that builds a new vector the same size as its input uses O(n) space.

Note

Time and space can trade off against each other. Later guides — starting with arrays — will point out exactly where that tradeoff shows up.
